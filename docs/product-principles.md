# Product principles

These principles are non-negotiable.

1. **Capture first. Organize later.** Writing and saving an Idea cannot require category, priority, status, tag, due date, or other metadata.
2. **Everything must be easy to find.** Search, clear navigation, Projects, Recent, Pinned, Archived, and Inbox or ungrouped handling prevent content from disappearing.
3. **Do not interrupt creativity.** Common actions require as few decisions and interactions as practical.
4. **Familiar over clever.** Prefer useful conventions from established developer tools, Windows, Discord, and Markdown.
5. **Multiple input methods.** Important actions should be available through obvious controls, menus, keyboard shortcuts, suitable context menus, slash commands, and Markdown-like input.
6. **Adaptive, not merely responsive.** Move, resize, collapse, or reorganize controls according to width, height, and aspect ratio; do not merely shrink desktop UI.
7. **Professional interface, subtle branding.** Use normal terms such as Ideas, Projects, Apps, Flowcharts, Snippets, Documents, Tasks, Archive, and Search.
8. **No unnecessary animation.** Motion communicates state, navigation, hierarchy, or progress; it is not decorative.
9. **Customization matters.** Plan for themes, fonts, scale, density, accent, icons, panel placement, toolbar and status configuration, editor preferences, shortcuts, mobile actions, and reduced motion.
10. **Work with developer tools.** Prefer interoperable, developer-friendly import and export such as Markdown and avoid lock-in where practical.

## Product tensions to preserve and resolve deliberately

- Traditional desktop menus and mobile navigation are separate presentations of shared actions.
- Desktop pinboard windows become lists, cards, or boards on mobile; coordinates are not shared content.
- Capture stays immediate while organization remains available afterward.
- Local-first reliability is required, while cloud synchronization remains undecided.
- Flexible blocks must have a sensible developer-friendly export representation.
- Customization must not erode predictable interactions or accessibility.
- Inline code blocks belong inside content; reusable Snippets are independent objects.
